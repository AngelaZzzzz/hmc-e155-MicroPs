Lab 6: The Internet of Things and Serial Peripheral Interface

STM32
C
SPI
Building an internet-connected device that toggles an LED and reports room temperature from a DS1722 SPI sensor, served by an ESP8266 web server over UART from the STM32L432KC
Author

Angela Zheng

Published

October 26, 2026

Introduction

The goal of this lab is to build a simple Internet of Things (IoT) device. An ESP8266 WiFi module hosts a web page that lets a user turn an LED on and off (on PA6) and view the current room temperature. The STM32L432KC MCU receives data from the temperature sensor via SPI, generates the HTML page, and sends data to the ESP8266 WiFI module via UART, which forwards it to the browser.

Beyond the LED control and temperature display, the web page also lets the user change the sensor’s resolution from 8 to 12 bits. The temperature is displayed with as many decimal places as the selected resolution provides, 0 for 8 bits, 1 for 9 bits, 2 for 10 bits, 3 for 11 bits, and 4 for 12 bits.

Design and Testing Methodology

The GPIO, RCC, FLASH, TIM, and USART libraries and the ESP8266 web server code are from Lab 6 starter code. I wrote the SPI driver (STM32L432KC_SPI.c/h), the DS1722 driver (DS1722.c/h), and the html request handler as well as the web page generator in main.c.

ESP8266–MCU interface

The ESP8266 interfaces with the MCU using USART1, with the MCU TX (PA9) connected to ESP’s RX and MCU RX (PA10) connected to ESP’s TX. Each time a browser loads the page, the ESP8266 sends the most recent request as /REQ:<tag>\n, and the main loop

  1. Reads characters from the UART until it sees \n.
  2. Checks the request for a resolution tag (res8 to res12) and reconfigures the DS1722 if one is present.
  3. Reads the temperature over SPI.
  4. Checks the request for ledon / ledoff and drives PA6.
  5. Sends the full HTML page, from <!DOCTYPE html> to </html>, back over the UART.

SPI driver

The SPI driver initializes SPI1 using initSPI(br, cpol, cpha):

  • Pin assignments: assigns SCK to PB3, MISO to PB4 and MOSI to PB5, and sets them all to alternate function 5. The chip enable CE is assigned to PB1.
  • CR1: enables master mode, software slave management (SSM, SSI), MSB first, and sets the baud rate, polarity, and phase according to the arguments.
  • CR2: sets an 8-bit data size (DS = 0b0111) and FRXTH, so RXNE flags after a single byte.

In main.c, The DS1722 is initialized with initSPI(0b111, 0, 1). This means that BR = 0b111, dividing the 80 MHz clock by 256, producing a 312.5 kHz SCK. This works because it’s under the DS1722’s 5 MHz maximum. CPOL = 0, CPHA = 1 configures data to change on the rising edge of SCK and sampled on the falling edge.

The SPI driver sends and receives data using spiSendReceive(): it first waits for TXE, writes one byte to DR, waits for RXNE, and then returns the received byte. DR is then accessed through an 8-bit pointer so that each write sends one byte only.

DS1722 driver

Every DS1722 transaction is an address byte followed by a data byte inside one chip-enable window. readTempRaw() combines the two bytes into a signed 16-bit value. The temperature in °C is then raw / 256.

Testing

  1. SPI without the temperature sensor. Before wiring the DS1722, I probed CE, SCK, MOSI and MISO with an oscop, using its logic analyzer function. I checked that the configuration write and the temperature reads produced the right addresses, data, clock polarity and phase, and chip-enable framing.
  2. SPI with the sensor. With the DS1722 connected, I probed the SPI channels again and checked that the MOSI and MISO bytes are as expected.
  3. Web page. I connected to the ESP8266’s access point, loaded http://192.168.4.1/, and checked that the temperature shown is reasonable, the LED buttons toggled the LED and its status text, and that each resolution button changed the number of decimal places shown.

Technical Documentation

Schematic

The DS1722’s VDDD, VDDA and SERMODE pins are all connected to the MCU’s 3.3 V supply. Pulling SERMODE high selects SPI mode on the temperature sensor. CE, SCK, SDO and SDI connect to PB1, PB3, PB4, and PB5, respectively. The ESP8266 is powered using 3.3 V, with its RX and TX connected to the MCU’s TX and RX. The LED is driven from PA6 through a 1 kΩ current-limiting resistor.

SPI Timing

Figure 2 shows one full temperature read SPI transaction. Channel 1 (yellow) is CE, 2 (green) is SCK, 3 (blue) is MISO, and 4 (pink) is MOSI. We can see that the first time CE is high, MOSI sends address 0x02 in the first 8 clock cycles and the DS1722 replies on MISO with the temperature MSB 0x17 (23 °C) in the second clock cycle. In the second time CE is high, MOSI sends 0x01 in the first 8 clock cycles and the DS1722 replies with the LSB 0x20 (0.125 °C) in the second 8 clock cycles. Combining the MSB and LSB, we get a temperature reading of 23.125 °C. And as for the clock period, we can see on the oscope trace that each grid is 11.6 microsecond, and we have approximately 4 clock cycles per grid, making each clock period around 2.9 microsecond. This indicates a clock of around 344 kHz, which is less than 5 MHz required by the DS1722, satisfying timing requirements.

Results and Discussion

The device works as intended. After connecting to WiFi provided by the ESP8266, the webpage at http://192.168.4.1/ shows the LED controls, the LED status, the current temperature, and the resolution buttons. Clicking Turn the LED on! or Turn the LED off! changes both the LED and its status text accordingly. The temperature reads about 23 °C, which is a reasonable room temperature.

Moreover, we have verified the SPI timing via the logic analyzer capture. Specifically, CE stays high for the whole two-byte transaction, data changes on the rising edge of SCK, and the sensor’s MISO bytes match the temperature on the web page.

The design meets all of the proficiency and execellence requirements.

Conclusion

The STM32L432KC microcontroller parses web requests from the ESP8266 over UART, controls an LED, reads temperature from the DS1722 over a CMSIS-based SPI driver, and sends back to the ESP8266 with an HTML page with the LED state and the current temperature at a selectable resolution.

I spent a total of 12 hours working on this lab.

/* ---------- Persistence (per-browser preferences) ---------- */
function loadPrefs() {
  try {
    const p = JSON.parse(localStorage.getItem("sensorPortalPrefs") || "{}");
    if (p.unit) state.unit = p.unit;
    if (Number.isInteger(p.precision)) state.precision = p.precision;
    if (p.apiBase !== undefined) CONFIG.apiBase = p.apiBase;
    if (p.pollMs) CONFIG.pollMs = p.pollMs;
    if (p.theme) document.documentElement.dataset.theme = p.theme;
    if (p.simulated !== undefined) state.simulated = p.simulated;
  } catch (_) { /* storage unavailable, use defaults */ }
}

function savePrefs() {
  try {
    localStorage.setItem("sensorPortalPrefs", JSON.stringify({
      unit: state.unit,
      precision: state.precision,
      apiBase: CONFIG.apiBase,
      pollMs: CONFIG.pollMs,
      theme: document.documentElement.dataset.theme || "",
      simulated: state.simulated
    }));
  } catch (_) { /* ignore */ }
}

  if (unit === "F") return c * 9 / 5 + 32;
  if (unit === "K") return c + 273.15;
  return c;
}

/* Map temperature (°C) to a color from cool blue to warm red */
function tempColor(c) {
  const t = Math.max(0, Math.min(40, c));
  const hue = 215 - (t / 40) * 215; // 215 (blue) -> 0 (red)
  return `hsl(${hue}, 85%, 62%)`;
}

async function fetchWithTimeout(url, options = {}) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), CONFIG.requestTimeoutMs);
  try {
    const res = await fetch(url, { ...options, signal: controller.signal });
    if (!res.ok) throw new Error("HTTP " + res.status);
    return await res.json();
  } finally {
    clearTimeout(timer);
  }
}

User Prompt

Write me a C function to carry out a SPI transaction to retrieve a temperature reading from a DS1722 sensor. Make use of CMSIS libraries for the STM32L432KC.

AI Response

This function reads the two-byte temperature register from a DS1722 using direct CMSIS register access on SPI1. It doesn’t depend on the HAL.

c
/*
 * ds1722.c
 * DS1722 digital thermometer over SPI for STM32L432KC (CMSIS, no HAL).
 *
 * Wiring (SPI1):
 *   PA5  -> SCK
 *   PA6  <- MISO (DS1722 SO)
 *   PA7  -> MOSI (DS1722 SI)
 *   PA4  -> CS   (active low, GPIO)
 *
 * Assumes the default 4 MHz MSI clock feeds PCLK2, so the SPI prescaler
 * divides by 2 for a 2 MHz SCK (DS1722 max is 2 MHz).
 */

#include "stm32l432xx.h"   /* CMSIS device header (includes core_cm4.h) */
#include <stdint.h>

#define DS1722_CS_PORT      GPIOA
#define DS1722_CS_PIN       4U

#define DS1722_REG_TEMP_MSB 0x01U   /* Temperature MSB register */
#define DS1722_REG_TEMP_LSB 0x02U   /* Temperature LSB register */

#define DS1722_READ_MASK    0x00U   /* Bit 7 = 0 for read  */
#define DS1722_WRITE_MASK   0x80U   /* Bit 7 = 1 for write */

#define SPI_TIMEOUT_LOOPS   10000U

typedef enum {
    DS1722_OK = 0,
    DS1722_ERR_TIMEOUT,
    DS1722_ERR_NULL
} ds1722_status_t;

/* -------------------------------------------------------------------------
 * Low-level helpers
 * ------------------------------------------------------------------------- */

static inline void ds1722_cs_low(void)
{
    DS1722_CS_PORT->BSRR = (1U << (DS1722_CS_PIN + 16U));   /* reset bit */
}

static inline void ds1722_cs_high(void)
{
    DS1722_CS_PORT->BSRR = (1U << DS1722_CS_PIN);           /* set bit */
}

/*
 * Full-duplex transfer of one byte. Returns the received byte, or
 * a negative value on timeout.
 */
static int spi1_transfer_byte(uint8_t tx, uint8_t *rx)
{
    uint32_t timeout = SPI_TIMEOUT_LOOPS;

    /* Wait until the transmit buffer is empty */
    while (!(SPI1->SR & SPI_SR_TXE)) {
        if (--timeout == 0U) return -1;
    }

    /* 8-bit access to DR so the frame is 8 bits, not 16 */
    *(volatile uint8_t *)&SPI1->DR = tx;

    /* Wait for a received byte */
    timeout = SPI_TIMEOUT_LOOPS;
    while (!(SPI1->SR & SPI_SR_RXNE)) {
        if (--timeout == 0U) return -1;
    }

    *rx = *(volatile uint8_t *)&SPI1->DR;
    return 0;
}

/* -------------------------------------------------------------------------
 * Initialization (call once at startup, after the system clock is set up)
 * ------------------------------------------------------------------------- */

void ds1722_spi_init(void)
{
    /* 1. Enable clocks for GPIOA and SPI1 */
    RCC->AHB2ENR |= RCC_AHB2ENR_GPIOAEN;
    RCC->APB2ENR |= RCC_APB2ENR_SPI1EN;

    /* 2. PA5 (SCK), PA6 (MISO), PA7 (MOSI) -> alternate function AF5 */
    GPIOA->MODER &= ~((3U << (5U * 2U)) | (3U << (6U * 2U)) | (3U << (7U * 2U)));
    GPIOA->MODER |=  ((2U << (5U * 2U)) | (2U << (6U * 2U)) | (2U << (7U * 2U)));
    GPIOA->AFR[0] &= ~((0xFU << (5U * 4U)) | (0xFU << (6U * 4U)) | (0xFU << (7U * 4U)));
    GPIOA->AFR[0] |=  ((5U   << (5U * 4U)) | (5U   << (6U * 4U)) | (5U   << (7U * 4U)));
    GPIOA->OSPEEDR |= ((3U << (5U * 2U)) | (3U << (7U * 2U)));  /* high speed SCK/MOSI */

    /* 3. PA4 as CS: plain push-pull output, idle high */
    GPIOA->MODER &= ~(3U << (DS1722_CS_PIN * 2U));
    GPIOA->MODER |=  (1U << (DS1722_CS_PIN * 2U));
    ds1722_cs_high();

    /* 4. SPI1 configuration */
    SPI1->CR1 = 0;                       /* disable before configuring */
    SPI1->CR1 |= SPI_CR1_MSTR;           /* master mode */
    SPI1->CR1 |= SPI_CR1_BR_0 & 0;       /* BR = 000 -> fPCLK/2 */
    SPI1->CR1 |= SPI_CR1_SSM | SPI_CR1_SSI; /* software NSS, avoid MODF */
    SPI1->CR1 &= ~SPI_CR1_LSBFIRST;      /* MSB first */
    SPI1->CR1 &= ~SPI_CR1_CPOL;          /* CPOL = 0 */
    SPI1->CR1 |= SPI_CR1_CPHA;           /* CPHA = 1 -> SPI mode 1 (verify vs datasheet) */

    /* 5. 8-bit data frame, RXNE at 8-bit threshold */
    SPI1->CR2 = SPI_CR2_FRXTH | (7U << SPI_CR2_DS_Pos);

    /* 6. Enable SPI */
    SPI1->CR1 |= SPI_CR1_SPE;
}

/* -------------------------------------------------------------------------
 * Temperature read
 * ------------------------------------------------------------------------- */

/*
 * Reads the DS1722 temperature register.
 *
 * Transaction (CS held low for the whole frame):
 *   Byte 1: command  = 0x01 (read, start at temperature MSB)
 *   Byte 2: dummy    -> receive MSB
 *   Byte 3: dummy    -> receive LSB
 *
 * On success, *temp_c is set in degrees Celsius.
 */
ds1722_status_t ds1722_read_temperature(float *temp_c)
{
    if (temp_c == NULL) {
        return DS1722_ERR_NULL;
    }

    uint8_t rx;
    uint8_t msb = 0U;
    uint8_t lsb = 0U;
    int     ret;

    ds1722_cs_low();

    /* Command byte: read, temperature register */
    ret = spi1_transfer_byte((DS1722_REG_TEMP_MSB & 0x7FU) | DS1722_READ_MASK, &rx);
    if (ret != 0) goto timeout;

    /* Clock out MSB */
    ret = spi1_transfer_byte(0xFFU, &msb);
    if (ret != 0) goto timeout;

    /* Clock out LSB */
    ret = spi1_transfer_byte(0xFFU, &lsb);
    if (ret != 0) goto timeout;

    /* Wait for the bus to go idle before releasing CS */
    {
        uint32_t t = SPI_TIMEOUT_LOOPS;
        while (SPI1->SR & SPI_SR_BSY) {
            if (--t == 0U) goto timeout;
        }
    }

    ds1722_cs_high();

    /* Combine into a signed 16-bit value; 8.8 fixed point (1/256 degC per LSB) */
    int16_t raw = (int16_t)(((uint16_t)msb << 8) | lsb);
    *temp_c = (float)raw / 256.0f;

    return DS1722_OK;

timeout:
    ds1722_cs_high();
    return DS1722_ERR_TIMEOUT;
}

{

    ds1722_spi_init();

    }

Things to verify against the DS1722 datasheet before relying on it:

SPI mode. I set CPOL=0, CPHA=1 (mode 1). Confirm this against the datasheet’s timing diagram, since flipping it is the most common cause of garbage readings. Temperature format. The code assumes a 16-bit, two’s-complement value with 1/256 °C per LSB. The DS1722 can report at lower resolutions, and the unused low bits depend on the resolution setting in the configuration register. Check the register map and adjust the scaling if needed. Configuration. The sensor’s power-up defaults may not be continuous conversion at the resolution you want. If you need a specific mode, write the configuration register (address 0x00, write mask 0x80) once after ds1722_spi_init(). Clock. The prescaler assumes PCLK2 is 4 MHz. If you change the system clock, adjust BR so SCK stays at or below 2 MHz.

Summary

AI’s website design is very meticulous, much better than what I had even envisioned. It included a much prettier user interface, included everything essential and even added temperature unit conversion and light/dark page style conversion.

The SPI function AI wrote on the other hand was less reliable. It drove CE active low when the DS1722’s CE is active high, and swapped the MSB (0x02) and LSB (0x01) addresses. Moreover, without enough context, it put MISO on PA6 which is my LED pin, further preventing the code it generator from working when plugged directly into my project. Therefore, I think the LLM is great for front-end design, but for low-level drivers it is still necessary to verify every register and design choice.
